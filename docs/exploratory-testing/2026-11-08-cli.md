# Exploratory testing: assumpgo CLI (2026-11-08)

This pass exercised the public CLI at `be63d25` (v0.1.11), on Linux amd64 with Go 1.26.8. The worktree held the binary, Go caches, module cache, and isolated fixtures. The module has no external dependencies; the build used `GOFLAGS=-mod=readonly`. No server, browser, container, or background process was started for the journeys.

The [replay script](2026-11-08-cli/replay.sh) recreates and removes its fixtures. The [captured output](2026-11-08-cli/replay-output.txt) came from the first complete run. A second complete run produced identical output. To replay, run `go build -o .scratch/bin/assumpgo ./cmd/assumpgo` and then run the script from the worktree. Git, Bash, Python 3, Go, and hard-link support are required.

## Journeys

1. **Gate a Go file.** A file with a bare variable, negative comparison, and positive equality produced two findings and exit 110. A positive-equality-only file produced no findings and exit 0. A parameter that shadows a package constant produced one finding and exit 110. The bundled `dog.go` smoke test produced one finding at line 12 and exit 110. The first script attempt expected three denominator expressions, but the documented rule also counts the `!=` node. The assertion was corrected to four before both complete replays.
2. **Select files for a build.** `project/...` reported the two root findings and skipped a finding in `testdata`. Excluding the root file yielded exit 0. A tagged file was skipped without `GOFLAGS` and reported with `GOFLAGS=-tags=special`. This variation retested the scenario in closed [issue #135](https://github.com/quality-gates/assumpgo/issues/135).
3. **Write a CI report without damaging an input.** The XML output file parsed with Python's standard XML parser and contained two findings at lines 3 and 4. The CLI wrote no report to stdout. Uppercase `XML` returned exit 100. An output path hard-linked to the input returned exit 100, and a byte comparison confirmed the input was unchanged.

## Findings and limitations

No bugs were confirmed and no new issues were filed. No candidates remain unresolved in these journeys. The issue and PR lists, labels, comments, and release list were checked before the pass. Existing open performance issues [#133](https://github.com/quality-gates/assumpgo/issues/133) and [#134](https://github.com/quality-gates/assumpgo/issues/134) were outside this functional pass. Open PRs [#111](https://github.com/quality-gates/assumpgo/pull/111) and [#72](https://github.com/quality-gates/assumpgo/pull/72) concern output formatting and were not changed.

Windows, non-UTF-8 paths, external CI consumers, and interactive terminal display widths were not exercised. XML was parsed locally, not imported into a CI product. The direct CLI output and saved report were checked rather than relying on exit status alone.

`go build ./...`, `go test ./...`, `go vet ./...`, `gofmt -s -l .`, `gocyclo -over 15 .`, and `ineffassign ./...` passed for tracked project files. The format check excluded the scratch directory. The local single-worker mutation gate was stopped after five minutes and returned 124, so it did not establish a mutation score. Git reported no tracked source changes after the stop. The PR workflows provide the full mutation gate.
