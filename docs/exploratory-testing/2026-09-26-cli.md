# Exploratory testing: assumpgo CLI (2026-09-26)

I drove the `assumpgo` binary through its public CLI, as a user would locally
and in CI.

- **Build:** `go build -o /tmp/assumpgo-explore/assumpgo ./cmd/assumpgo` from a
  clean worktree at `d322d4f` (v0.1.7), go1.26.6 darwin/arm64. The checkout I
  started in had an uncommitted version-string bump; I did not test that.
- **Readiness:** `assumpgo testdata/fixtures/dog.go` gave one `if dog != nil {`
  row and exit 110.
- **Data:** throwaway modules under `/tmp`, plus read-only scans of this repo
  and the sibling `mutago` checkout.
- **Evidence:** [`2026-09-26-cli/replay.sh`](2026-09-26-cli/replay.sh) replays
  every confirmed finding against a binary you pass in.
  [`2026-09-26-cli/replay-output.txt`](2026-09-26-cli/replay-output.txt) holds
  three consecutive runs.

## Journeys

| # | User goal | Satisfied when | Result |
| - | :--- | :--- | :--- |
| 1 | Gate a module with `assumpgo ./...`, as the README CI snippet does | Files the go tool ignores cannot abort the run or flip the exit code; findings match the documented rules on code that does compile | Fails: F1, F2 |
| 2 | Produce a checkstyle report and leave noisy paths out (`-format xml -output`, `-exclude`) | The file matches stdout, is valid XML, the exit code matches the findings, and `-output` does not truncate analysed source | Passes on the ordinary path |
| 3 | Read a pretty finding and open the cited line | The line number and message identify that source line, and the table lines up in the terminal | Fails: F3, F4 |

What I tried on each journey:

- **Journey 1.** Ran `./...` on a small multi-package module (comma-ok, a
  cross-file const, `testdata`, `vendor`, a hidden directory, a `_` directory),
  on assumpgo itself (508 of 1229 boolean expressions, 41%, exit 110), and on
  `mutago` (783 of 2419, 32%, exit 110, about 0.04s). Variations: a syntax
  error in `*_windows.go`, in `//go:build ignore`, and in `//go:build windows`;
  a valid assumption in `*_windows.go`; a name that is a `const` under
  `windows` and a `var` otherwise; piping the report to `head`.
- **Journey 2.** Wrote checkstyle XML to stdout and to `-output` (byte-identical,
  `xmllint` clean on the self-scan). Variations: refusing to overwrite a target
  via a relative path, an absolute path, a symlink, and a hard link; `-output`
  to a missing parent and to a directory; a control character in a finding
  line; the README command `-exclude vendor,testdata ./mypackage` from the
  parent directory.
- **Journey 3.** Checked line numbers against the source for ordinary, multiline,
  CRLF, and no-trailing-newline files. Variations: CJK, `café`, a flag emoji,
  `❤️`, a ZWJ sequence, and an ESC colour sequence in the finding line. Also
  re-checked the documented detection rules (positive `==`, package consts,
  comma-ok including generic and parenthesized forms, mixes, pure var chains).

## Confirmed bugs

Each bug reproduced 3/3 from a clean temp dir with `replay.sh`.

### F1: `./...` analyses files the go tool ignores ([#104](https://github.com/quality-gates/assumpgo/issues/104))

- **Impact:** On darwin, `sys_windows.go` is not part of the build (`go list`
  puts it in `IgnoredGoFiles`, `go vet ./...` exits 0). A syntax error in that
  file makes `assumpgo ./...` exit 100 and print no findings for the files that
  do compile. The same abort happens for `//go:build ignore` and
  `//go:build windows`. A valid `if x != nil` in `sys_windows.go` fails the
  gate with exit 110. The README CI snippet is `assumpgo ./...` on one OS.
- **Expected:** Directory walks and `./...` skip files the go tool would not
  compile for the default context. Naming such a file directly still analyses
  it, as with `_disabled.go`.
- **Actual:** `go vet` exit 0 and assumpgo exit 100 (syntax error), or exit 110
  (valid assumption in the unbuilt file).

### F2: a const in a build-excluded file hides an assumption ([#105](https://github.com/quality-gates/assumpgo/issues/105))

- **Impact:** `if Enabled` refers to `var Enabled` on darwin and to
  `const Enabled` only in a `//go:build windows` file. The code vets clean.
  The gate exits 0. Deleting the windows-only file makes the same line exit
  110. Naming `use.go` directly is enough; the sibling still poisons the
  const index. `GOOS=windows` does not change assumpgo's result.
- **Expected:** Exit 110 and a finding on `use.go`. A const declared in a file
  that is part of the same build is still not flagged.
- **Actual:** `0 out of 1 boolean expressions are assumptions`, exit 0.

### F3: pretty table misaligns on flag emoji and variation-selector symbols ([#106](https://github.com/quality-gates/assumpgo/issues/106))

- **Impact:** A finding whose line contains `🇬🇧` or `❤️` makes that row
  shorter than the border in a macOS terminal. CJK and `café` on other lines
  still align. Same failure mode as #23, #69, and #78, for characters those
  fixes do not cover.
- **Expected:** Every table line has the same terminal width as the border.
- **Actual:** libc `wcswidth` is 40 vs a 42-column border for the flag, and
  40 vs 41 for `❤️`.

### F4: pretty output writes raw terminal escapes from the source line ([#107](https://github.com/quality-gates/assumpgo/issues/107))

- **Impact:** An ESC colour sequence in a comment on the finding line is copied
  to stdout. The terminal applies it, and `wcswidth` of the row is -1, so the
  closing `|` does not sit on the border. XML replaces the control character
  and is fine.
- **Expected:** The report does not send terminal control sequences. The table
  stays aligned. The exit code still reflects the findings.
- **Actual:** Two `1b` bytes in the pretty row. Exit 110.

## Unresolved candidates

- **Comma-ok from a function call is flagged.** `if v, ok := os.LookupEnv("X"); ok`
  and the inverted form both exit 110. `docs/usage.md` still limits comma-ok
  to type assertions, map indexes, and channel receives, so this matches the
  written contract. The README's shorter "fix it with a comma-ok" wording does
  not.
- **Tagless `switch` cases.** `case verbose:` is not flagged. `case x != nil:`
  is, because `!=` is flagged wherever it appears. The detection rules do not
  mention `switch`.
- **Hard-link aliases still flip constant resolution.** The real path exits 0
  (sibling const seen). A hard link of that file in another directory exits
  110. A symlink of the same file stays 0. usage.md says the index is the
  directory alongside the path you passed, and a hard link has no single
  canonical directory, so I did not file this.

## Usability observations

- `assumpgo -h` still exits 100. Flags after the path are still parsed as
  paths (`assumpgo ./... -format xml` → `stat -format`).
- The README command `assumpgo -exclude vendor,testdata ./mypackage`, run from
  the parent of `mypackage`, does not exclude `mypackage/testdata`. A broken
  fixture there aborts the run with exit 100. From inside `mypackage`,
  `-exclude vendor,testdata .` does exclude them. Same cwd resolution as #18.
- A checkstyle `<error>` still has no `column`. Three findings on
  `analyser.go:206` are three identical elements.
- `-format xml` has no assumption ratio. The ratio is only on the pretty
  summary line. Exit 110 still fails the gate.
- An empty directory, a directory with no `.go` files, and a directly named
  FIFO all print `0 out of 0` and exit 0.
- `-output other.go`, when `other.go` was not a target, truncates that file
  and replaces it with the report. The documented guard only covers analysed
  targets. I reproduced that on a temp file.
- One unreadable `.go` file, or an unreadable subdirectory, aborts the whole
  run with exit 100 and no report. That is the same exit-code mapping as #68
  (collect for a directory, `Analyse` for a file).
- The self-scan table is hundreds of columns wide because the message is the
  whole source line.

## Rejected candidates

- **XML and a control character in the finding line.** The report is written,
  exit 110, and the byte is replaced with U+FFFD. Not an abort.
- **`assumpgo ./... | head`.** The scanner's exit status stays 110.
- **Symlink const resolution, overwrite guards, FIFO-in-a-walk.** Still behave
  as after #86, #50, and #97. A walked directory that contains a FIFO named
  `pipe.go` still reports the other file and does not hang.
- **Documented detection rules on code that compiles together.** Positive `==`,
  same-package consts (including a sibling file and an internal `_test.go`),
  external `package p_test` not seeing `p`'s const, a local var shadowing a
  const, generic and parenthesized comma-ok, inverted guards, `ok && v != 0`
  reporting the `!=` only, pure var chains, and two comparisons. All matched
  the docs.
- **Multiline `!=`, CRLF, and a missing trailing newline.** Line numbers are
  the physical lines of the expressions.
- **Strings and comments.** `if x != nil` inside them is not flagged.
- **`./...` and dot/`_`/`testdata`/`vendor`.** The small module's hidden,
  `_draft`, `testdata`, and `vendor` trees were not in the `./...` report.
  A plain directory walk of the same tree still parses `testdata` and exits
  100, which usage.md describes.

## Not explored

- Windows paths and drive letters.
- Non-UTF-8 filesystem encodings.
- An extra `-tags` set. The CLI has no such flag. Default context only.
