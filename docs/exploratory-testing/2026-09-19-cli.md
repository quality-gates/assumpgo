# Exploratory testing: assumpgo CLI (2026-09-19)

I drove the `assumpgo` binary through its public CLI, as a user would locally
and in CI.

- **Build:** `go build -o /tmp/assumpgo-explore/assumpgo ./cmd/assumpgo` at
  `248519d` (v0.1.5), go1.26.6 darwin/arm64.
- **Readiness:** `assumpgo testdata/fixtures/dog.go` gave one `if dog != nil {`
  row and exit 110, as expected.
- **Data:** throwaway temp directories. I also ran read-only scans of the sibling
  `mutago` checkout and the Go toolchain's `src/`.
- **Evidence:** [`2026-09-19-cli/replay.sh`](2026-09-19-cli/replay.sh) replays
  every confirmed finding against a binary you pass in.
  [`2026-09-19-cli/replay-output.txt`](2026-09-19-cli/replay-output.txt) holds
  three consecutive runs.

## Confirmed bugs

Each bug reproduced 3/3 from a clean temp dir with `replay.sh`.

### F1: `./...` walks hidden, `_`, `testdata` and `vendor` directories ([#85](https://github.com/quality-gates/assumpgo/issues/85))

- **Impact:** in `mutago`, 919 of 1732 reported assumptions came from a hidden
  `.claude/worktrees/` copy of the repo. A single deliberately invalid
  `testdata/*.go` fixture aborts the whole run with exit 100. The Go toolchain's
  `go/parser/...` hits this.
- **Expected:** `./...` skips what Go's `./...` skips (`go list`/`go vet` do).
- **Actual:** all five copies of `f.go` are analysed, and the broken fixture
  exits 100.
- **Related:** the README's `-exclude vendor,testdata ./mypackage` resolves
  excludes against the current directory. Run from a parent directory, it
  silently excludes nothing, because missing exclude paths are ignored by design
  (#18).

### F2: a symlinked file resolves constants from the link's directory ([#86](https://github.com/quality-gates/assumpgo/issues/86))

- **Impact:** `if Debug {` (a constant declared in a sibling file) is falsely
  flagged, and the exit code flips from 0 to 110 depending on the path used to
  reach the same file.
- **Expected:** exit 0 for `real/a.go`, `other/a.go` (symlink) and `other/`.
- **Actual:** exit 0, 110, 110.

### F3: `//line` directives break locations and messages ([#87](https://github.com/quality-gates/assumpgo/issues/87))

- **Impact:** in generated code, findings point at a line that doesn't exist
  and have an empty message.
- **Expected:** `gen.go | 5 | if x != nil {`.
- **Actual:** `gen.go | 100 | ` (the logical `grammar.y` line, paired with the
  physical file name).

## Unresolved candidates

These might be bugs, but I couldn't tie them to a documented expectation. None
was filed.

- **Comma-ok from a function call is flagged.** For example,
  `if v, ok := os.LookupEnv("X"); ok`. `docs/usage.md` lists only type
  assertions, map indexes and channel receives as comma-ok, so this matches the
  written contract. It is still the most common Go comma-ok idiom, and the
  README's advice to "fix the check to a ... comma-ok" doesn't clear it.
- **Tagless `switch` cases are neither flagged nor counted.** For example,
  `switch { case verbose: }`, which is semantically `if verbose`. The detection
  rules don't mention `switch`.

## Usability observations

These are what I saw. Suggestions are marked separately.

- `assumpgo -h` exits 100, the documented "usage error" code. Go's
  `flag.ExitOnError` convention exits 0 for help.
- Flags after a path aren't parsed. `assumpgo ./pkg -format xml` fails with
  `error: stat -format: no such file or directory`.
- The usage text lists flags but not the positional `<path>...` argument.
- A checkstyle `<error>` has no `column`. Two `!=` findings on one line produce
  identical elements that can't be told apart.
- Rounding can print `1 out of 252 boolean expressions are assumptions (0%)`
  while the gate fails with exit 110.
- A directory with no `.go` files reports `0 out of 0` and exits 0. A typo
  that still names an existing directory passes the gate silently.
- Suggestion: follow Go's `./...` semantics (F1) and warn when an `-exclude`
  entry matches nothing.

## Rejected candidates

- **XML escaping of `<&"'>` in messages.** The output is valid.
- **CRLF sources.** Line numbers and messages are correct; the trailing `\r`
  is trimmed.
- **Directory symlinks for constant resolution.** These resolve correctly;
  only file symlinks fail (F2).

## Not explored

- Hard-link aliases for constant resolution. These can't be resolved from the
  path alone.
- FIFOs and other non-regular files named `*.go`.
- Unreadable (permission-denied) subdirectories.
- Windows paths.
