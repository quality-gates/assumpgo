What I tried on each journey:

- **Journey 1.** Evaluated detection rules on realistic Go control flow:
  - Comma-ok expressions (`type assertions`, `map index`, `channel receive`) in
    both `:=` and `=` forms, inverted guards `!ok`, parenthesized forms `(ok)`
    and `(!ok)`.
  - Multi-branch `else if` chains inheriting comma-ok bindings across multiple
    conditions, rebinding with another comma-ok, and rebinding with non-comma-ok
    assignments.
  - Calling expressions, composite literals, and closures in condition
    expressions, confirming that comma-ok exemptions stop at non-logical
    boundaries (#117, #123).
  - Package-level constants across sibling files included in the build context,
    constant shadowing by local variables, and build-excluded sibling files.
  - Negative comparisons (`!=`) across `if`, `for`, assignments, and `return`
    statements, as well as strict equality assertions (`==`) including `x == nil`.
  - Scanned `assumpgo` itself (590 of 1445 boolean expressions, 41%, exit 110)
    and `mutago` (829 of 2549 boolean expressions, 33%, exit 110).
- **Journey 2.** Exercised target path collection and filesystem interactions:
  - Recursive directory walks with `...`, verifying skipped directories
    (`.`, `_`, `testdata`, `vendor`) vs direct targeting.
  - Build tag handling in directory walks: build-excluded platform files
    (`sys_windows.go`, `//go:build ignore`) are skipped during walks (#104),
    while invalid build directives in walked directories fail fast with exit 100
    (#124).
  - Symlinks and hard links: directory symlink traversal without cycles, cyclic
    symlinks visited once without infinite loops, dangling symlinks skipped
    during walks.
  - Non-regular files: FIFOs (named pipes) skipped during directory walks without
    blocking or hanging, and direct targeting of FIFOs exits 0 without hanging.
  - `-output` overwrite protection: attempts to write to analysed target files
    (via relative, absolute, symlink, or hardlink paths) are refused with exit
    100 before file truncation.
- **Journey 3.** Inspected rendered outputs and report formats:
  - Pretty table output across complex Unicode lines: ASCII, Latin accents
    (`café`), CJK ideographs, Hangul syllables, symbols, emojis, regional
    indicator flags (`🇬🇧`), variation selectors (`\ufe0f`), and multiline
    expressions. Verified row width matches border width across all rows.
  - ANSI terminal escape sequences (`\x1b[31m`) and C0/C1 control characters in
    scanned source lines are sanitized to visible escapes (`\x1b`), preventing
    terminal state corruption and alignment breaks (#107, #114).
  - Checkstyle XML (`-format xml`): special XML characters (`&`, `<`, `>`, `"`,
    `'`) properly escaped, illegal XML 1.0 control characters sanitized to
    `\ufffd`, valid XML verified with `xmllint --noout -`, and clean exit on
    zero-assumption inputs (`<checkstyle></checkstyle>`).
  - Output to stdout vs `-output <file>`: byte-for-byte identical output for
    both pretty and xml formats.

## Unresolved candidates

- **Comma-ok from function calls is flagged.** `if v, ok := os.LookupEnv("X"); ok`
  and its inverted form exit 110. `docs/usage.md` limits comma-ok assertions to
  type assertions, map indexes, and channel receives.
- **Tagless `switch` cases.** `case ready:` is not flagged as a bare variable
  condition, whereas `case x != nil:` is flagged because `!=` is flagged wherever
  it appears. The detection rules in `docs/usage.md` do not mention `switch`.
- **Hard-link aliases across directories.** Sibling constant lookup resolves
  relative to the containing directory of the specified path. A hard link
  residing in another directory without sibling constant declarations does not
  resolve constants from the original directory.

## Usability observations

- `assumpgo -h` exits 100 with usage text on stderr.
- Flags passed after positional targets (e.g. `assumpgo ./... -format xml`) are
  parsed as positional paths by Go's standard `flag` package, attempting to stat
  `-format`.
- Directly naming build-excluded files (e.g. `_disabled.go` or `*_windows.go`)
  analyses them, whereas directory walks skip them.
- `-format xml` does not report the summary assumption ratio (denominator),
  focusing purely on `<error>` tags for CI checkstyle parsers.

## Rejected candidates

- **Parenthesized comma-ok conditions in else-if chains.** `else if (ok)` and
  `else if (!ok)` correctly unwrap parentheses and remain exempt from bare-variable
  or unary-not assumptions.
- **Multi-variable assignments in else-if inits.** `else if ok, _ := fn(); ok`
  correctly recognizes that `ok` was rebound by a non-comma-ok assignment and
  flags `ok` as a bare variable condition.
- **Non-regular FIFO files.** Creating a named pipe (`pipe.go`) inside a walked
  tree does not cause the walker to hang or fail; the FIFO is skipped cleanly.
- **Checkstyle XML with special characters in file paths.** File paths
  containing `&`, `<`, `>`, or quotes are properly escaped in XML attributes and
  pass `xmllint --noout -`.
