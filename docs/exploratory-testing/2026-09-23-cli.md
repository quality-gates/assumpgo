# Exploratory testing: assumpgo CLI (2026-09-23)

I drove the `assumpgo` binary through its public CLI, as a user would locally
and in CI.

- **Build:** `go build -o /tmp/assumpgo-explore/assumpgo ./cmd/assumpgo` at
  `7ace731` (v0.1.7), go1.26.6 darwin/arm64.
- **Readiness:** `assumpgo testdata/fixtures/dog.go` gave one `if dog != nil {`
  row and exit 110, as expected.
- **Data:** throwaway temp directories, synthetic modules, and edge-case code
  snippets covering Go language features.
- **Evidence:** [`2026-09-23-cli/replay.sh`](2026-09-23-cli/replay.sh) replays
  every confirmed finding against a binary you pass in.
  [`2026-09-23-cli/replay-output.txt`](2026-09-23-cli/replay-output.txt) holds
  three consecutive runs.

## Journeys

| # | User goal | Satisfied when | Result |
| - | :--- | :--- | :--- |
| 1 | Gate a module with `assumpgo ./...` | Only the module's buildable source is analysed; files ignored by Go toolchain are skipped; exit code reflects gate result | Fails: F1 |

What I tried on each journey:

- **Journey 1.** Ran `./...` on clean modules, modules with `.hidden.go` and
  `_disabled.go` files, modules with macOS AppleDouble metadata (`._main.go`),
  and modules with Emacs/editor lock files. Variations: constant resolution across
  sibling files where constants are declared in `_`-prefixed files; target paths
  with trailing `/...`; plain directory walks (`assumpgo .`); target files
  specified directly.
- **Journey 2.** Evaluated complex control flow and assertion constructs:
  comma-ok map lookups (`if v, ok := m[k]; ok`), type assertions (`x.(T)`),
  channel receives (`<-ch`), inverted guards (`!ok`), parenthesized conditions
  (`(!ok)`, `!(ok)`, `(!((ok)))`), compound conditions (`ok && v != nil`,
  `!ok || v == ""`, `!ok || v != ""`), comma-ok inside `for` loops
  (`for v, ok := <-ch; ok;` and `for v, ok := <-ch; !ok;`), pure variable
  chains (`a && b && c`), bare variable conditions, strict positive equality
  (`==`) vs negative inequality (`!=`), generic type assertions, and closure
  boundaries.
- **Journey 3.** Generated checkstyle XML and pretty table outputs to stdout and
  files (`-output`). Variations: overwriting existing non-target report files,
  refusing overwrite on analysed targets (`main.go`, `./main.go`, `sub/main.go`,
  symlinks, and hard links), pointing `-output` at existing directories or
  missing parent directories, empty result reporting (`0 out of 0`), and XML
  attribute escaping for special characters (`<`, `>`, `&`, `"`, `'`).

## Confirmed bugs

Each bug reproduced 3/3 from a clean temp dir with `replay.sh`.

### F1: `./...` and directory walks collect hidden and `_`-prefixed files ignored by Go ([#101](https://github.com/quality-gates/assumpgo/issues/101))

- **Impact:**
  - Go's toolchain (`go build`, `go vet`, `go list`) unconditionally ignores
    files and directories whose names begin with `.` or `_` (`go help packages`:
    "Directory and file names that begin with '.' or '_' are ignored by the go
    tool, as are directories named 'testdata'"). While issue #85 fixed skipping
    *directories* under `...` patterns, `walkGoFiles` still collects individual
    *files* starting with `.` or `_`.
  - On macOS, when unpacking archives or working on network/USB volumes,
    AppleDouble files (`._*.go`) containing binary metadata are created.
    `assumpgo ./...` attempts to parse them and crashes the entire run with
    `error: ._main.go:1:1: illegal character NUL` (exit 100), whereas `go vet ./...`
    succeeds with exit 0.
  - In Go codebases, prefixing a file with `_` (e.g. `_old.go` or `_draft.go`) is
    a standard idiom to disable code without deleting it or switching branches.
    `assumpgo ./...` analyses these files, falsely failing CI gates or reporting
    parse errors on draft syntax.
  - `scanDirConsts` parses `_`-prefixed files, incorrectly registering constants
    from unbuilt files and treating bare variable checks as assertions even though
    the compiler rejects them as undefined.
- **Expected:** `./...` and walked directories skip files whose names start with
  `.` or `_`, matching Go's toolchain behavior. Directly naming an excluded file
  (`assumpgo _disabled.go`) can still analyze it as an explicit opt-in.
  `scanDirConsts` ignores `.` and `_` prefixed files.
- **Actual:** `._main.go` aborts the scan with exit 100; `_disabled.go` is analysed
  and flagged with exit 110; constants in `_consts.go` leak into `scanDirConsts`.

## Unresolved candidates

- **Comma-ok from function calls is flagged.** For example,
  `if v, ok := os.LookupEnv("X"); ok`. Matches the documented contract in
  `docs/usage.md`, which defines comma-ok as type assertions, map lookups, and
  channel receives.
- **Silent no-op when `-exclude` matches nothing.** Excluding a non-existent path
  silently excludes nothing (intentional design per #18).

## Usability observations

- Checkstyle `<error>` elements have no `column` attribute. Multiple assumptions
  on the same line (e.g. `if !a && !b {}` or `if x != nil && y != nil {}`) produce
  identical `<error>` elements that cannot be distinguished in CI parsers.
- When all targets are excluded via `-exclude` (e.g. `assumpgo -exclude main.go main.go`),
  `assumpgo` outputs `0 out of 0 boolean expressions are assumptions (0%)` and
  exits 0.

## Rejected candidates

- **Compound comma-ok with inverted guards.** `if v, ok := m[k]; !ok || v == ""`
  passes cleanly with 0 assumptions (2 boolean expressions).
- **Parenthesized comma-ok expressions.** Forms such as `(!ok)`, `!(ok)`, and
  `(!((ok)))` are all recognized as inverted comma-ok assertions without being flagged.
- **Range statements without conditions.** `for range slice` and `for i := range 10`
  are not boolean expressions and are not counted in the denominator.
- **Filesystem overwrite protections.** `-output` successfully detects and refuses
  overwriting analysed files when given relative paths (`./main.go`), absolute
  paths, directory targets (`sub/main.go`), symlinks, or hard links.

## Not explored

- Windows paths and drive letters.
- Non-UTF8 filesystem encodings.
